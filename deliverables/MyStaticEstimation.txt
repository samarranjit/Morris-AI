CS4346 Morris AI - MyStaticEstimation.txt
Improved static estimation (Part IV)

The project handout asks this file to explain:
  1. the features used by the evaluation function,
  2. why they were selected,
  3. how they are combined,
  4. why the result is better than the original evaluation function,
and to give at least two board positions where the improved function selects
a different move than the original one (section 5).

Programs: MiniMaxOpeningImproved.py and MiniMaxGameImproved.py.
They use the same MINIMAX search as MiniMaxOpening.py and MiniMaxGame.py.
Only the static estimation function is different. Code: morris/improved.py.


1. FEATURES USED

Each feature is computed for both players. The score uses the difference,
White's count minus Black's count, so a positive score favors White. The Black
programs swap colors before searching, so for them a positive score favors Black.

P  Pieces: number of pieces on the board.
M  Mills: completed mills. Each of the 18 mill lines is counted once.
O  Open mills: mill lines with exactly two own pieces and one empty location.
C  Connections: for every own piece, the number of mill lines through its
   location, added together. For example, a6 lies on three lines and d0 on one.
T  Threats: legal moves that would close a mill. The moving piece cannot be one
   of the two pieces that have to stay in that mill.
V  Mobility: number of legal moves, before counting the different captures a
   move could make. A player with exactly three pieces can hop, so every empty
   location counts for each of its pieces. Otherwise only adjacent empty
   locations count.
B  Blocked pieces: pieces with no legal move. A player who can hop is never
   blocked by occupied neighbors.

The opening uses P, M, O, C. The midgame/endgame uses P, M, T, V, B.


2. WHY THESE FEATURES WERE SELECTED

Pieces (P). The game is won by reducing the opponent to two pieces, so material
is the most important term in both phases.

Opening (O, C, M). The original opening function is only the piece difference.
Before the first capture it gives every placement the same score, so it cannot
tell a useful placement from a useless one. Open mills are captures that one more
placement can make. Connections reward locations that belong to several mill
lines, which gives more ways to build a mill later.

Midgame/endgame (T, V, B, M). In the moving phases two pieces on a line are not
enough: a piece has to be able to slide into the empty location, and that piece
cannot be one of the two already on the line. T counts only those reachable
mill-closing moves. Mobility matters because a player with no legal move loses,
and a player with few moves is close to being blocked. Blocked pieces cannot
help until a route opens. Completed mills describe the current structure, but
they get less weight than material and real threats.

All features are simple counts on the board. The function does no search of its
own, so it stays fast at every leaf of the search tree.


3. HOW THE FEATURES ARE COMBINED

Weighted sum of the White-minus-Black differences:

  Opening score         = 100*P + 20*O + 10*M + 3*C
  Midgame/endgame score = 1000*P + 60*T + 25*M + 5*V - 20*B

Game results come first in the midgame/endgame:
  +10000 if Black has 2 or fewer pieces,
  -10000 if White has 2 or fewer pieces.
The search also scores a position as lost for the player to move when that
player has no legal move. Ordinary scores are limited to the range -9000..9000,
so positional terms can never outrank a won or lost game.

Material has the largest weight, so the positional terms mostly decide between
moves that keep material equal. Several positional terms together can still
outweigh one piece, for example many threats plus much higher mobility. The
weights were chosen by hand from these priorities; they are not learned or
proven optimal.


4. WHY IT IS BETTER THAN THE ORIGINAL FUNCTION

Original opening:          numWhitePieces - numBlackPieces
Original midgame/endgame:  1000*(numWhitePieces - numBlackPieces) - numBlackMoves

  - The original opening score is the same for almost every placement. The new
    one prefers placements that create mill chances and use well-connected
    locations, before any capture is possible.
  - The original midgame score looks only at Black's mobility. The new one
    measures both players' mobility, blocked pieces, and reachable mill threats.
  - The original counts one generated position per possible capture, so a move
    that can capture several different pieces inflates numBlackMoves. The new
    mobility counts each move once.

Section 5 shows two positions where this changes the move, with the reason the
new move is better. In a small local test (four games at depth 2, the same
alpha-beta search for both sides, colors swapped), the improved function won
three games and drew one against the original function. That is a small
sample, not proof that it is stronger against every opponent.


5. POSITIONS WHERE THE IMPROVED FUNCTION SELECTS A DIFFERENT MOVE

Both positions are the boards drawn in the Morris Variant handout. Both use
MINIMAX at depth 2. Examples.txt shows the full program output for each.

Example 1 - opening
  Input board:     WxWWxWWWWWBBBBBBBBxxxxx
  Original move:   WWWWxWWWWWBBBBBBBxxxxxx   (place at d0, capture b5)
  Improved move:   WxWWxWWWWWBBBBBBBxxxWxx   (place at a6, capture b5)
  Why: both moves close a mill and capture the same Black piece, so the
  original function scores them the same and takes the first one. The improved
  function prefers a6, which lies on three mill lines, over d0, which lies on
  one. After the move White's connection advantage is 7 instead of 5, its
  mobility advantage is +2 instead of 0, and White has one more blocked piece
  than Black instead of two more. The search also checked Black's reply at
  depth 2.

Example 2 - midgame
  Input board:     xxxxxBxWWWWWBBBBxxxxxxx
  Original move:   xxxxxBxWWWWxBBBBWxxxxxx   (slide e3 to e4)
  Improved move:   xxxxxBxWWxWWBBBBxWxxxxx   (slide b3 to b5)
  Why: the improved move opens White's a3-b3-c3 mill by sliding b3 to b5.
  The piece can slide back next turn to close the mill again, which is a real
  capture threat; the threat difference becomes +1 instead of 0. It also gives
  White more freedom: mobility +3 instead of +1, and one fewer blocked piece
  than Black instead of an equal number. The original move keeps the mill
  closed but leaves White with fewer moves and no threat. These are positional
  reasons, not a proof of a forced win.


RULE INTERPRETATION

The last line of GenerateRemove (Morris Variant handout, page 4) adds the board
when no piece was removed. We read this as: if every opposing piece is in a mill,
the mill-closing move is kept without a capture. The handout's use of b is
ambiguous; this is our interpretation, not an instructor clarification.
