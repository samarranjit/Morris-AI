CS4346 Morris AI - Examples.txt

This file answers two requirements of the project handout:
  Part II: at least two cases where ALPHA-BETA evaluates fewer positions than MINIMAX,
           with the same MINIMAX estimate and the same move.
  Part IV: at least two board positions where the improved static estimation selects
           a different move than the original one, with a reason for preferring it.

Each case shows the exact command and the three lines the submitted program printed.
Input files are the two positions drawn in the Morris Variant handout:
  handout_position_1.txt = xxxxxBxWWWWWBBBBxxxxxxx
  handout_position_2.txt = WxWWxWWWWWBBBBBBBBxxxxx
Depth counts individual turns (plies). "Positions evaluated" counts calls to the static estimator.
Capture rule used: when every opposing piece is in a mill, the mill-closing move is kept
without a capture (last line of GenerateRemove, Variant p. 4).
Regenerate: python3 tools/verify_project.py --examples-only


PART II: ALPHA-BETA EVALUATES FEWER POSITIONS THAN MINIMAX

Case 1 (opening, depth 3)
Input board: xxxxxBxWWWWWBBBBxxxxxxx

MINIMAX:
  $ python3 MiniMaxOpening.py handout_position_1.txt board2.txt 3
  Board Position: xxxxxxxWWWWWBBBBWxxxxxx
  Positions evaluated by static estimation: 3778
  MINIMAX estimate: 2

ALPHA-BETA:
  $ python3 ABOpening.py handout_position_1.txt board2.txt 3
  Board Position: xxxxxxxWWWWWBBBBWxxxxxx
  Positions evaluated by static estimation: 481
  MINIMAX estimate: 2

Selected move: White places a piece at e4 and removes the Black piece at f1
Same move and same MINIMAX estimate (2). Alpha-beta evaluated 481 positions instead of 3778 (87% fewer).
Alpha-beta stops exploring a branch once it cannot change the decision above it.
Both searches try moves in the same order and keep the first move on a tie.

Input board: WxWWxWWWWWBBBBBBBBxxxxx

  Positions evaluated by static estimation: 544
  MINIMAX estimate: 993

ALPHA-BETA:
  $ python3 ABGame.py handout_position_2.txt board2.txt 3

  MINIMAX estimate: 993

Selected move: White moves a0 to d0
Same move and same MINIMAX estimate (993). Alpha-beta evaluated 129 positions instead of 544 (76% fewer).

PART IV: IMPROVED STATIC ESTIMATION SELECTS A DIFFERENT MOVE
Scores from the two estimators use different scales. Compare the chosen moves, not the numbers.

Case 1 (opening, depth 2)
Input board: WxWWxWWWWWBBBBBBBBxxxxx

ORIGINAL ESTIMATION:
  $ python3 MiniMaxOpening.py handout_position_2.txt board2.txt 2
  Board Position: WWWWxWWWWWBBBBBBBxxxxxx
  Positions evaluated by static estimation: 76
  MINIMAX estimate: 1
  Move: White places a piece at d0 and removes the Black piece at b5

IMPROVED ESTIMATION:
  $ python3 MiniMaxOpeningImproved.py handout_position_2.txt board2.txt 2
  Board Position: WxWWxWWWWWBBBBBBBxxxWxx
  Positions evaluated by static estimation: 76
  MINIMAX estimate: 162
  Move: White places a piece at a6 and removes the Black piece at b5

Feature differences after each move (White minus Black):
  original move: {'pieces': 2, 'mills': 1, 'open_mills': 3, 'mobility': 0, 'blocked': 2, 'threats': 1, 'connections': 5}
  improved move: {'pieces': 2, 'mills': 1, 'open_mills': 3, 'mobility': 2, 'blocked': 1, 'threats': 1, 'connections': 7}

Why the improved move is preferred: Both moves close a mill and remove the same Black piece, so the original function gives them the same score and keeps the first one, d0. The improved function prefers a6, which lies on three mill lines, over d0, which lies on one. After the move White's connection advantage is 7 instead of 5 and its mobility advantage is +2 instead of 0, so White has more ways to build its next mill. The search also checked Black's reply at depth 2.

Case 2 (midgame, depth 2)
Input board: xxxxxBxWWWWWBBBBxxxxxxx

ORIGINAL ESTIMATION:
  $ python3 MiniMaxGame.py handout_position_1.txt board2.txt 2
  Board Position: xxxxxBxWWWWxBBBBWxxxxxx
  Positions evaluated by static estimation: 57
  MINIMAX estimate: -13
  Move: White moves e3 to e4

IMPROVED ESTIMATION:
  $ python3 MiniMaxGameImproved.py handout_position_1.txt board2.txt 2
  Board Position: xxxxxBxWWxWWBBBBxWxxxxx
  Positions evaluated by static estimation: 57
  MINIMAX estimate: -45
  Move: White moves b3 to b5

Feature differences after each move (White minus Black):
  original move: {'pieces': 0, 'mills': 1, 'open_mills': -1, 'mobility': 1, 'blocked': 0, 'threats': 0, 'connections': -1}
  improved move: {'pieces': 0, 'mills': 0, 'open_mills': 0, 'mobility': 3, 'blocked': -1, 'threats': 1, 'connections': -1}

Why the improved move is preferred: The improved move opens White's a3-b3-c3 mill by sliding b3 to b5. The piece can slide back next turn to close the mill again, which is a real capture threat: the threat difference becomes +1 instead of 0. It also gives White more freedom: mobility +3 instead of +1, and one fewer blocked piece than Black instead of an equal number. The original move, e3 to e4, keeps the mill closed but leaves White with fewer moves and no threat. These are positional reasons, not a proof of a forced win.
